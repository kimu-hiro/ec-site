# コーディング規約
 - 読みやすいコードを心がける

## 名前
 - あちこち変数を使いまわすと、辿るのが大変になるため、基本的な方針として変数は少なく、使う範囲はなるべく狭くする。

 - PHP の変数と関数の名前には、スネークケース(小文字と _)を使う(例:contents_of_cart)

 - 定数の名前は全部大文字と _ を使う（例:DB_NAME）

 - 名前は極力分かりやすく。tmp・data・key のようなぼんやりした名前は避け、必要なら単位も入れる（例： $normalized_area_text、REFRESH_MS）

 - true/false が入る変数は is・has で始める（例：$is_logged_in・$has_stock）

## 見た目（字下げ・空白）
 - インデントは半角の空白4つ

 - 見た目をなるべくそろえる（並び順・書き方）

 - ?> のあとに、空白や改行がうっかり残るとエラーに繋がるので、PHP だけのファイルの終わりには'?>'をつけない

## 関数
 - 一つの関数には1つの仕事だけ（単一責任）。2つ以上あれば関数を分け、まとめ役の関数から順に呼ぶ

 - 初学者でも分かる基本的な関数や機能をなるべく使う（例：array_mapのような書き方より、foreach と if）。別の書き方が「大幅に分かりやすい」「手間が大きく減る」「格段に速い」ときだけ使う。その場合は使っている理由を、コメントで説明する

 - なるべく短いコードにする。使わない機能を作らない。用意されている道具があれば使う（ただし初学者向けの方針を優先）

 - if の入れ子を深くせず、だめなときは先に return で抜ける

 - 長い式は分けて、途中に名前を付ける
## コメント
 -  「何をする」より**「なぜ」**を書く

 -  関数定義する際、すぐ上に PHPDoc（/** */）で説明を書く。ふだんのメモは // で書く

## 安全のための決まり
 - 入力された文字を画面に出すときは、h() を通す（XSS を防ぐ）

 - DB に問い合わせるときは、プレースホルダーを使う(SQLインジェクションを防ぐ)

## ファイルと置き場所
 - ユーザーが開くファイル（Controller）は htdocs/ec_site/ に置く

 - ユーザーがURLから開けないように DB とやり取りするファイル（Model）はinclude/model/ に置く

 - ユーザーが外から開けないように 画面の HTML（View）は include/view/に置く

 - 直す時に一箇所だけで済むよう、変わらない値（DB の名前など）はinclude/config/const.php にまとめる

 - サーバーの引越しをしても、パスを書き換えなくて良いよう、リンクは相対パスを使う
