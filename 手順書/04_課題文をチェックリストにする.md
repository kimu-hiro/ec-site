# 04 課題文を、1行ずつのチェックリストにする

## 何のためか

買い物に行く前に、買う物のメモを作る段。
課題文は長いので、読みながら作ると、どこかを必ず忘れる。
先に「やること」を1行ずつに分けておけば、
あとは上から印を付けていくだけになる。

- 新しく覚えること：Markdown のチェック欄 `- [ ]`
- 新しく入れるもの：無い

## できあがりの形

```
ECsite/
  ├ 手順書/
  │   └ 04_課題文をチェックリストにする.md（これ）
  └ 書類リスト/
      └ 課題チェックリスト.md   ← 今日作るのはこれ
```

- 提出する書類ではない。作り忘れを防ぐ、自分用のメモ
- 05〜31 の段は、このメモを見ながら進める

## 1. ファイルを作る

VS Code で `書類リスト/課題チェックリスト.md` を作り、
1行目に題名だけ書いて保存する。

```markdown
# 課題チェックリスト
```

- `#` ＝ 見出しの印。1つなら一番大きい見出し

## 2. 課題文の「見出し」だけを写す

ポータルの課題文を開く。
（ITEX利用者ポータル → テキスト → PHP/MySQL
　→ 最終課題：ECサイト）

中身はまだ写さない。大きな見出しだけを、
`##` を付けて上から順に並べる。

```markdown
# 課題チェックリスト

## 書類
## （課題文の、次の見出し）
## （課題文の、その次の見出し）
```

- `##` ＝ 2番目の大きさの見出し
- 見出しの名前は、課題文と同じにする
  （あとで課題文と見比べやすくするため）

先に見出しだけ並べるのは、本の目次を先に見るのと同じ。
「全部で何の話があるか」が先に分かる。

## 3. 見出しの下に、やることを1行ずつ書く

見出しを1つずつ読み、「やること」を `- [ ]` で書く。

例（書類の見出しの場合）：

```markdown
## 書類

- [ ] ページ一覧（マスト）：URL・名前・概要を必ず入れる
- [ ] 画面遷移図（マスト）
- [ ] コーディング規約（マスト）
- [ ] テーブル定義書（ベター）
- [ ] ER図（ベター）
```

- `- [ ]` ＝ まだのチェック欄。`-` と `[` の間に空白、
  `[` と `]` の間にも空白を1つ入れる
- 済んだら `- [x]` にする（`x` は小文字）

分け方の決まり：

| 決まり | 例 |
|---|---|
| 1行に、やることは1つ | 「登録と入力チェック」は2行に分ける |
| 「必ず」と「できれば」を分ける | 行の終わりに（マスト）（ベター） |
| 数字や名前は落とさない | 「6ページ」「URL・名前・概要」 |

## 4. 自分の言葉で、短く書く

課題文をそのままコピーして貼らない。
読んで、自分の言葉で短く書き直す。

理由は2つ：

1. 書き直せる ＝ 意味が分かっている、の確かめになる。
   書き直せない行は、分かっていない行
2. このリポジトリは Public（だれでも見られる）。
   教材の文をそのまま大量に載せるのは避けたい

書き直せない・意味が分からない行は、
行の終わりに `？` を付けて、そのまま次へ進む。

```markdown
- [ ] 〇〇を△△する ？
```

止まって考えこまない。`？` の行は、最後に
Claude か支援員さんに、まとめて聞く。

## 5. 抜けがないか、見比べる

全部書けたら、課題文とメモを左右に並べる。
課題文の見出しを1つずつ指でなぞり、
メモに同じ見出しがあるか、行が抜けていないかを見る。

VS Code の画面半分にメモ、
もう半分にブラウザの課題文、の形が見やすい。

## 6. Claude に見せる

ファイルを保存して、「書けた」と Claude に伝える。
Claude はこのファイルを読めるので、次を一緒に見る。

- 1行に2つ以上のことが入っていないか
- `？` の行の意味
- 課題の要点（PARA の記録）と比べて、抜けが無いか

## 7. git に入れる

Claude に見てもらって直し終わったら、自分で commit・push する。

```bash
git add 書類リスト/課題チェックリスト.md
git commit -m "課題チェックリストを作る"
git push
```

- `-m` ＝ message ＝ その場で commit の説明を書く

## つまずいたら

| 出たもの | 意味 | 直し方 |
|---|---|---|
| チェック欄にならず `[ ]` がそのまま見える | 空白が足りない | `- [ ]` の形か見る。`-[ ]` や `- []` はだめ |
| 見出しにならず `##` がそのまま見える | `##` のあとに空白が無い | `## 書類` のように空白を1つ入れる |
| 課題文が長すぎて疲れた | ふつう | 見出し1つ分で保存して休む。続きは次の日でよい |

ここに無いことで困ったら、Claude に聞く。

## できたら

- [x] 課題文の見出しが全部、メモに並んだ
- [x] 見出しの下に、やることが1行ずつ書けた
- [x] Claude に見せて、`？` の行が片付いた
- [x] commit・push した

できたら、かかった時間を Claude に伝える。
`00_全体の道のり.md` の表には Claude が書く。
