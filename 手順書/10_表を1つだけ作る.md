# 10 表を1つだけ作る（ユーザーの表）

## 何のためか

09 で**倉庫（`ec_site`）と鍵（`ec_user`）**を作った。
10 は、倉庫に**棚（表）を1つだけ**建てる段。残り4つは 11。

```
ec_site（倉庫。もうある）
  └ ユーザーの表   ← 今日建てる1つ目の棚
    （画像・商品・在庫・カートは 11）
```

- 新しく覚えること：`CREATE TABLE`（表を作る命令）と、
  `setup.sql`（表の作り方を書いた紙）
- 新しく入れるもの：無い

### なぜ1つだけなのか

5つ一気に書くと、エラーが出たとき**原因が分からない**。
1つ作って動かし、確かめてから次を足す。

最初に作れるのは、**他の表に頼っていない表**。
在庫やカートは、番号札（外部キー）で他の表を指すので、
相手の表が先に無いと作れない。

```
親（FK なし）   子（FK あり）
商品 ───────→ 在庫・画像・カート
ユーザー ────→ カート
```

親は商品とユーザーの2つ。**どちらを先に作ってもよい**。
ユーザーにしたのは段取りの都合で、決まりではない。

- 13〜15 のログインで最初に使うので、動かして確かめやすい
- 08 で決めた「パスワードは60文字以上」をここで試せる

### なぜ 09 と違って、ファイル（`setup.sql`）に書くのか

| | 09（倉庫と鍵） | 10 から（表） |
|---|---|---
| 書く場所 | ターミナルに直接 | `setup.sql` というファイル |
| git | 入れない | 入れる |
| 理由 | パスワードが入る | 表の作り方に秘密が無い |

ファイルにしておくと、サーバー側では phpMyAdmin に同じ中身を
貼るだけで、**Mac とまったく同じ表**ができる。
書きまちがえても、ファイルを直して流し直せる。

### `setup.sql` をどこに置くか

`db/` という新しいフォルダを作って、その中に置く。

```
ec-site/
  ├ db/
  │   └ setup.sql   ← 今日作る。ブラウザからは見えない
  ├ htdocs/
  │   └ ec_site/    ← ブラウザから見える場所
  └ include/
```

`htdocs` の下に置かない理由：そこは外から見える場所なので、
`http://localhost:8000/setup.sql` を開かれると、
**表と列の名前が丸見え**になる。
設計図は外に出さない。

※ この置き場所は課題の指示には無い（Claude の提案）。
　 別の名前にしたいときは、`db` を好きな名前に変えてよい。

## できあがりの形

- ファイルが1つ増える：`db/setup.sql`
- `ec_site` の中に、表が1つできる

## 1. 入れ物のファイルを作る

まずは**コメント1行だけ**のファイルから始める。

```bash
mkdir -p db
```

- `mkdir`＝make directory＝フォルダを作る
- `-p`＝parents＝途中のフォルダも必要なら作る。
  すでにあってもエラーにしない

VS Code で `db/setup.sql` を作り、1行だけ書く。

```sql
-- ec_site の表を作る紙
```

- `--`（ハイフン2つ）から行の終わりまでは SQL のコメント。
  **`--` のあとに半角スペースが1つ要る**

## 2. 設計図を見る

08 で作った `書類リスト/04_テーブル定義書.pdf` を開き、
ユーザーの表を見る。
見るのは5つ。

- 列の名前
- 型（`INT`・`VARCHAR(100)` など）
- 空でもよいか（`NOT NULL`）
- 主キー（PK）と自動採番（A_I）
- 同じ値を2つ入れさせない列（ユニーク）

## 3. `CREATE TABLE` を書く

`setup.sql` に、ユーザーの表を作る命令を足す。

ヒント：

- 調べる言葉：`MariaDB CREATE TABLE 書き方`
- 自動採番と主キー：`MariaDB AUTO_INCREMENT PRIMARY KEY`
- 命令の形は

```sql
CREATE TABLE 表の名前 (
    列の名前 型 決まり,
    列の名前 型 決まり
);
```

- 1つの列を1行に書く。字下げは半角4つ（07 の規約どおり）
- **最後の列のうしろにカンマを付けない**（1064 の原因）
- パスワードの列は60文字以上（`password_hash` が返す長さ。
  08 で決めた）
- 文字の種類は書かない。倉庫を `utf8mb4` にしたので、
  何も書かなければ表もそれを引き継ぐ

## 4. 紙を流しこむ

```bash
mariadb -u ec_user -p ec_site < db/setup.sql
```

| 部分 | 意味 |
|---|---
| `-u ec_user` | user＝入る人の名前。09 で作った鍵を使う |
| `-p` | password＝パスワードを聞いてもらう |
| `ec_site` | どの倉庫で実行するか。付け忘れると 1046 エラー |
| `< db/setup.sql` | `<` ＝ファイルの中身を、手で打ったのと同じように渡す |

何も出なければ成功（SQL は、うまくいくと黙っている）。

## 5. できたか確かめる

```bash
mariadb -u ec_user -p ec_site -e "SHOW TABLES;"
```

- `-e`＝execute＝実行する。命令を1つ打って、すぐ戻る

表が出たら、中の列も見る。

```bash
mariadb -u ec_user -p ec_site -e "DESCRIBE 表の名前;"
```

- `DESCRIBE`＝describe＝説明する。`DESC` と略せる
- 定義書と見くらべる。型・長さ・`NULL`・`Key` が合っているか

## 6. 作り直したいとき

```sql
DROP TABLE 表の名前;
```

- `DROP`＝落とす・捨てる。**中のデータごと消える**

`setup.sql` の `CREATE TABLE` の上に次の行を置いておくと、
流すたびに作り直せる。

```sql
DROP TABLE IF EXISTS 表の名前;
```

- 作っている間だけ便利。データが入ったら**危ない**ので、
  そのとき外すかどうかを決める

## 7. git に入れる

パスワードが入っていないことを目で確かめてから。

```bash
git add db/setup.sql
git status
```

`git status` に `db/setup.sql` だけが出ていれば OK。
`git add -n db` なら、足さずに「何が足されるか」だけ見られる
（`-n`＝`--dry-run`＝予行演習）。

確かめたら、記録に残して GitHub に送る。

```bash
git commit -m "DB：まずは users の表だけ作る"
git push
```

- `-m`＝message＝この変更が何なのかを1行で書く
- `git status` が `nothing to commit, working tree clean`、
  `git push` のあと `ahead of 'origin/main'` が消えれば終わり

## つまずいたら

| 困ったこと | 直し方 |
|---|---
| `ERROR 1046 No database selected` | どの倉庫か言っていない。`mariadb -u ec_user -p ec_site < …` の `ec_site` を付ける |
| `ERROR 1050 Table … already exists` | もう作ってある。`SHOW TABLES;` で確かめ、作り直すなら `DROP TABLE` |
| `ERROR 1064 … syntax` | カンマ・かっこ・`;` のどこか。最後の列のうしろのカンマ、閉じかっこ、行末の `;` を見る |
| `ERROR 1142 … command denied` | `ec_user` が開けない倉庫をさわっている。倉庫の名前を見る |
| `ERROR 1071 Specified key was too long` | ユニークや主キーを付けた文字の列が長すぎる。`utf8mb4` は1文字4バイトなので、`VARCHAR(255)` だと上限を超える。長さを短くする |
| コメントが命令として読まれる | `--` のあとに半角スペースが無い |
| `->` が出て止まった | `;` を忘れている。`\c` で打ちかけを捨てる |
