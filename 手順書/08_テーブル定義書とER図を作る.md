# A テーブル定義書

## A-1. 表の数と名前を決める

課題文（課題チェックリスト）に、テーブルの例が書いてある。
まずそれを、表の名前（英語の小文字と `_`）にする。

例（1つだけ）：

```
ユーザーの表 → user
```

ヒント：

- 名前は 07 のコーディング規約（スネークケース）にそろえる
- 表の名前を単数（`user`）にするか複数（`users`）にするか
  決めて、全部そろえる（テキストは `product` で単数）

## A-2. 1つ目の表（ユーザー）だけ書く

いきなり全部書かない。まず1つ。

`書類リスト/04_テーブル定義書.xlsx` を作り、次の形で書く。
（はじめはマークダウンで書いたが、表が作りにくいので
Excel にした。現場でもテーブル定義書は Excel が多い）

```
ユーザーテーブル
No. | カラム名 | カラム名（日本語） | 型 | NULL | キー | 説明
1   | user_id  | ユーザーid        | int| 不可 | PK/A_I | …
```

| 列 | 意味 |
|---|---|
| カラム名 | 列の名前 |
| 型 | 入る値の種類（下の表） |
| NULL | 空のままでよいか（可・不可） |
| キー | PK・A_I・UNIQUE・FK のどれか（無ければ空） |
| 説明 | 何が入るか |

- PK ＝ Primary Key ＝ 主キー。その行を1つに決める番号
- A_I ＝ Auto Increment（自動で増える）。1・2・3…と DB が振る
- UNIQUE ＝ 同じ値を2回入れさせない
- FK ＝ Foreign Key ＝ 外部キー（A-4 で使う）

よく使う型（18_2 のテキストに出てきた物）：

| 型 | 入る物 | 例 |
|---|---|---|
| `int` | 整数 | 番号・値段・在庫数 |
| `varchar(100)` | 文字（かっこの中は最大の文字数） | 名前 |
| `datetime` | 日付と時刻 | 登録した日時 |

user の表に、残りの列を足す。ヒント：

- ログインに使う物は何か（課題チェックリストのログインの所）
- 同じユーザー名を2回登録させない決まりがあった。
  それはどのキーで守れるか
- パスワードは `password_hash` の形で入れる（決めた方針）。
  長さは 255 にしておくと安心
  （PHP の公式が、将来もっと長くなっても入るように、と
  すすめている長さ）

## A-3. 外部キーの無い表を、先に全部書く

ほかの表を指さない表から書く。
（どの表がそうかは、A-4 を読んでから考えてもよい）

## A-4. 外部キーで、表と表をつなぐ

そもそも外部キーは、**ほかの表の主キーを、自分の列に持つ**こと。
18_2 の `product` の `category_id` がそれ。

```
category（カテゴリー）
  category_id ← 主キー
       ↑ 指さす
product（商品）
  category_id ← 外部キー
```

こうしておくと、無いカテゴリーの番号（18_2 のコロッケ）を
入れようとしたとき、DB が断ってくれる。

キーの列には、どこを指すかも書く。

```markdown
| category_id | int | 不可 | FK → category.category_id | カテゴリー |
```

ヒント：

- カートの表は、「だれの」「どの商品が」「何個」の3つを持つ。
  「だれの」と「どの商品が」は、どの表を指せばよいか
- 商品の名前や値段は、カートの表に**写さない**。
  商品の番号だけ持てば、商品の表から引ける。
  これが 15 の正規化の考え方（同じことを2か所に書かない）

## A-5. 課題チェックリストと見比べる

チェックリストの各ページの行を見て、
「この値は、どの表のどの列に入るか」を1つずつ指でなぞる。
入る場所が無い値があれば、列が足りない。

例：

```
「公開ステータス」を切りかえる → どの表のどの列？
```

# B ER図

## B-1. ER図とは

- ER ＝ Entity Relationship
  （entity＝もの・表、relationship＝つながり）

テーブル定義書の表を箱にして、外部キーの所を線でつないだ図。
06 の画面遷移図の「箱と矢印」と同じ描き方で描ける。
ちがうのは、線に**「1」と「多」**を書くこと。

## B-2. 「1対多」の読み方

例：カテゴリーと商品

```
category（1）───────（多）product
```

- 1つのカテゴリー（野菜）に、商品はたくさん入る
- 1つの商品が入るカテゴリーは、1つだけ

外部キーを持つ側が「多」、指される側が「1」になる。

線の端の書き方は、いくつか流儀がある。
いちばん簡単なのは、線の両はしに `1` と `N`（たくさん）と
文字で書く方法。これで十分。

（本物の ER図では、「多」の側を鳥の足のような
3本線で描く書き方もよく使われる。
興味があれば「IE記法」で画像検索）

## B-3. Excel で描く

06 と同じやり方。

1. `書類リスト/05_ER図.xlsx` を作る
2. 表ごとに箱を1つ。箱の中の1行目に表の名前、
   その下に列の名前を並べる
3. PK の列には `(PK)`、FK の列には `(FK)` と付ける
4. FK の列から、指す表の PK の列へ線を引く
5. 線の両はしに `1` と `N` を書く

すみに、凡例（`1`・`N`・`PK`・`FK` の意味）を置く。

## B-6. git に入れる

Excel のファイルを git に入れないように、`.gitignore` を確かめる。
今は `02_画面遷移図.xlsx` の名前だけ書いてあるので、
このままだと `05_ER図.xlsx` は外れない。
（ヒント：`*` を使うと、1行で Excel を全部外せる）

```bash
git status
```

`.xlsx` が出なければ OK。

```bash
git add .gitignore 書類リスト/04_テーブル定義書.pdf 書類リスト/05_ER図.png
git commit -m "テーブル定義書とER図を作る"
git push
```
